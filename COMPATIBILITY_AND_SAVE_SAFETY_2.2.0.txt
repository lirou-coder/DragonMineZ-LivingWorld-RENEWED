LIVING WORLD 2.2.0 — COMPATIBILITY / SAVE SAFETY
====================================================
Target stack
- Minecraft 1.20.1
- Forge 47.4.10
- Dragon Mine Z 2.1.3
- GeckoLib 4.8.4
- Java 17
- Curios 5.14.1+1.20.1 / TerraBlender 3.0.1.10 as part of the target DMZ stack.

Save compatibility
- The runtime source in this final publication tree is byte-identical to the accepted R45 gameplay tree.
- mod ID and ambient_fighter registry ID are unchanged from the published line.
- Every public 1.9.0 SavedData filename remains present with the same name.
- Public 1.9.0 player persistent roots remain recognized.
- Current fighter/entity persistence uses default-based/additive loading for newer fields.
- Retired Mentor/Student and obsolete request fields are explicitly migration-cleaned.
- Newer systems (World Menace and Red Ribbon Experiment SavedData) are additive and initialize if absent.
- Networking deliberately rejects mismatched old/new clients; that is multiplayer protocol safety and does
  not alter on-disk save compatibility.

Mod compatibility / authority
- No Dragon Mine Z, Forge, GeckoLib, Curios or TerraBlender classes are shaded into Living World.
- Client GUI/render/particle state remains client-side; world/fighter state is server-authoritative.
- Settings writes remain permission-gated where server-owned.
- Ordinary simulation does not install persistent forced-chunk tickets.
- Temporary props/sessions retain cleanup and persistence guards.

Removal note
Removing a content mod that owns custom entities can remove those entities when chunks load without the
mod. Back up before uninstalling or changing major versions.
